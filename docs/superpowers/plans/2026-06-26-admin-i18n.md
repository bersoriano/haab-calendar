# Booking App Phase 2 Admin i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire all provider-facing (admin) surfaces of the booking app to the existing `lang` value so that a provider who selects Español sees their own dashboard, bookings list, admin calendar, setup wizard, settings, and service editor in Spanish.

**Architecture:** `lang`, `copy`, and `t` are already derived at lines 311–313 of `components/haab-booking-module.tsx` as closures over the provider's store. All admin render functions inside that file automatically have access to them — no threading needed there. The only components that need a new `lang` prop are the two extracted ones: `ServiceEditor` and `ProviderInfoForm`. The dictionary (`translations.ts`) gains four new groups (`admin`, `setup`, `welcome`, `providerForm`) and three keys added to the existing `public` group. One new formatter (`getBookingStatusLabel`) goes in `lib/format.ts`. The English path stays byte-for-byte unchanged (all new params default to `"en"`).

**Tech Stack:** Next.js 16 / React 19, TypeScript, Vitest. es-MX formal `usted`.

## Global Constraints

- All new `lang` parameters default to `"en"` — no existing call site breaks.
- Admin surfaces translate when `provider.language === "es"`; English is the default.
- The Language selector labels ("Language", "English", "Español") in Settings intentionally stay English — do not translate them.
- `copy.*` strings are already language-keyed from Phase 1 — do not duplicate them in the dictionary.
- `getBookingTypeLabel(type, lang)`, `formatDuration(service, lang)`, `formatCapacityLabel(service, lang)` already support `lang` — just pass it.
- TypeScript (`npx tsc --noEmit`) and `npm run build` must pass after every task.
- Run `npx vitest run` after Task 1 to verify the parity test catches any missing keys.

- [ ] **Step 3: Add getBookingStatusLabel to lib/format.ts**

Append at the end of `lib/format.ts` (after the existing exports):

```ts
const STATUS_LABELS: Record<Lang, Record<BookingStatus, string>> = {
  en: { confirmed: "Confirmed", rescheduled: "Rescheduled", cancelled: "Cancelled" },
  es: { confirmed: "Confirmado", rescheduled: "Reagendado", cancelled: "Cancelado" },
};

export function getBookingStatusLabel(status: BookingStatus, lang: Lang = "en"): string {
  return STATUS_LABELS[lang]?.[status] ?? status;
}
```
